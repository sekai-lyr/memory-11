# 卡牌爆裂启动视觉规格

## 目标

把 Sekai Game 的大厅从静态 Hero 页面改成以卡牌演出为核心的“决斗启动场”。用户进入首页时看到的是一叠封印牌，而不是营销文案；揭牌、散牌、主卡翻面和功能入口入场共同组成一次可重播的启动演出。

## 视觉判断

- 受众：喜欢二次元角色卡牌和游戏王式回合制决斗的玩家。
- 视觉密度：低到中。舞台留黑，卡牌和信息只在需要的时刻出现。
- 设计拨杆：`DESIGN_VARIANCE 9`、`MOTION_INTENSITY 10`、`VISUAL_DENSITY 3`。
- 色彩：以墨黑、纸白、金色冲击色为骨架，卡牌自身的紫、蓝和红作为局部光源，不再使用整屏紫色渐变。
- 资产：优先使用当前收藏中的真实卡图；人物竖卡用于主卡，横向双人/场景卡用于飞掠卡，金色冲击卡用于冲击帧，透明 mascot 用作导航引导。

## 首页结构

1. `ignition-stage`：全屏舞台、牌堆、飞掠卡、主卡和冲击光圈。
2. `ignition-copy`：主卡翻面后出现的短标题、当前卡组状态和决斗入口。
3. `ignition-dock`：卡组、收藏和每日目标的三个低密度状态读数。
4. 现有业务按钮继续保留：挑战关卡、练习决斗、创建/加入房间和编辑卡组。
5. 现有收藏卡牌点击和详情逻辑继续保留。

## 动效分镜

```text
0ms       舞台只有牌背、细环和“CARD IGNITION”提示。
120ms     牌背向后压缩，中心白光和斜切光出现。
180ms     8 张真实卡图沿不同弧线飞出，间隔 35ms。
420ms     主卡绕 Y 轴翻面，同时背景卡降低亮度。
620ms     标题按词/行进入，卡组状态从底部锁定。
780ms     操作入口从舞台边缘撞入，按钮落地一次。
1100ms    舞台进入稳定态；鼠标移动只产生轻微视差，不循环播放爆发。
```

## 交互

- 点击“揭牌·开始决斗”执行同一套爆裂后进入训练决斗。
- 点击“挑战关卡”先执行短版落场冲击，再打开现有关卡选择弹窗。
- 点击飞掠卡进入现有收藏页并选中该卡。
- 点击“重播演出”只重播一次，不自动循环。
- `prefers-reduced-motion` 或设置中的减少动态效果开启时，直接显示稳定态。

## 后续演出：卡包过载与召唤落场

### B：卡包过载

- 现有抽卡确认和概率逻辑不变，只替换抽取结果前后的视觉层。
- 点击确认抽取后，卡包先被压缩、撕开，8 张结果卡以 42ms 间隔从中心甩出。
- 最高稀有度卡牌在最后一张落位，使用金色/紫色的稀有度色，不用全屏随机彩色粒子。
- “揭晓结果”仍然是明确按钮；用户可以跳过演出直接查看结果。
- 十连抽只展示前 8 张和最高稀有度卡，避免 10 张卡同时堆叠造成噪声。

### C：召唤落场

- 现有挑战关卡、练习决斗和 PvP 创建成功回调不变，进入 `onStartDuel` 前播放短版落场。
- Web：选中的主卡沿 Z 轴旋转，砸入战场；背景卡被拉成速度线，中心冲击环只播放一次。
- Godot：启动层完成后保留同一时间点，在 `start_demo_duel()` 之前播放卡背到战场的落场动画。
- 对局真正初始化只发生一次；动画跳过、网络失败或 reduced-motion 都必须走原有回调。

## 性能与无障碍

- 只对 `transform`、`opacity`、`filter` 做动画；不动画 `top/left/width`。
- 普通卡牌采用 anime.js `waapi.animate()`，时间偏移使用 `stagger()`。
- 主卡翻面、文案和落场使用 `createTimeline()`；文案拆分使用 `splitText()`。
- 同时可见的动态卡牌最多 8 张；小屏只保留 4 张。
- 动画取消时清理 Web Animations；稳定态内容必须在无动画时可读。
- Godot 入口使用 `AnimationPlayer/Tween` 复刻同一时间节点，不引入 Web 依赖。

## 不在本次范围

- 不修改卡牌规则、抽卡概率、账户接口、PvP 协议或数据库结构。
- 不把首页演出扩展成持续粒子背景或自动轮播，以免影响阅读和低端设备性能。
- 不替换已有卡图文件；正式发布前仍需确认二次元素材授权。
