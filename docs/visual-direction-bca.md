# B+C+A 视觉实施方向

## 设计判断

这是一个面向二次元卡牌玩家的全量游戏 UI 改造。现有卡牌插画是主资产，界面不再使用通用紫蓝后台作为主角，而是围绕卡牌材质、角色舞台和决斗镜头建立统一语言。

## 三条路线的分工

### A：卡牌圣殿

- 卡框、稀有度、属性和箔光负责身份；
- 收藏和卡组页面优先保证卡牌可读性；
- 卡牌详情像图鉴和卡册，而不是普通信息卡片；
- 采用 4 / 8 / 12px 的锐利圆角尺度；
- 页面基础色是墨黑、纸白和卡牌金。

### B：决斗超载

- 关键规则事件才触发强演出；
- 召唤、攻击、陷阱、破坏、回手、除外和胜负各有独立节奏；
- 镜头使用单一 camera transform 层，不允许多个函数互相覆盖；
- 每次演出都可取消、跳过、完成和回收；
- 强动画只消费结构化事件，不参与规则判断。

### C：角色舞台

- 首页和卡包优先呈现真实卡图与角色关系；
- 每张高稀有度角色卡可拥有签名色、签名粒子和签名入场方式；
- 角色卡的视觉配置来自卡牌元数据，不在 effects.js 中继续堆名称判断；
- 角色演出不能覆盖 LP、目标、攻击结果等核心信息。

## 页面分工

| 页面 | 主要语言 | 重点 |
| --- | --- | --- |
| 登录/注册 | C + A | 角色卡环绕，卡框式认证面板 |
| 首页 | C | 真实卡图 Hero、角色签名、进入决斗 |
| 卡包 | B + C | 撕包、稀有度节奏、角色登场 |
| 收藏 | A + C | 图鉴、卡框、箔光、角色档案 |
| 卡组 | A | 拖拽组牌、合法性、策略信息 |
| 决斗 | B + A | 场地、卡牌身份、镜头和冲击 |
| PvP | A + E | 清晰状态、同步、读秒、动作确认 |
| Godot | A + B | 同一张卡的身份和规则演出语义 |

## 动效原则

1. 简单的 transform、opacity 和卡牌入场优先使用 Anime.js WAAPI。
2. 多阶段的召唤、攻击和卡包演出使用单一 timeline。
3. 不动画化 top、left、width、height 等布局属性。
4. 不使用无限循环装饰来填充页面。
5. 每个动画必须说明它表达的是层级、反馈、状态变化或叙事。
6. reduced motion 下保留信息顺序，取消粒子、镜头和循环。
7. 所有临时 DOM、动画句柄和 class 必须有统一清理路径。

## 第一阶段实现边界

- 给 body 增加 bca 视觉路由标识；
- 统一基础 token，移除页面主色对 AI 紫色的依赖；
- 建立卡框和战斗镜头的基础变量；
- 不改决斗规则、不改卡牌数据、不改变 API 字段；
- 以后再把 effects.js 的旧/新演出收束到 VisualDirector。

## 后续顺序

1. 卡牌身份层和视觉 token；
2. 首页、登录、卡包、收藏、卡组；
3. VisualDirector 和决斗事件；
4. 召唤、攻击、陷阱、破坏、胜负；
5. PvP、Godot、服务端事件协议；
6. 性能、可访问性、视觉回归和完整测试。
